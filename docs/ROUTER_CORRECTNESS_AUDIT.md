# Router correctness audit

Audit date: 2026-10-22. Scope: the existing 18 families in `src/cisco/router/` and `tests/cisco_router.rs`. No additional command families, Packet Tracer execution, private fixtures, GUI automation, push, or release were performed.

## Evidence boundary

The official Cisco pages below were browsed during this audit. The current IOS XE 17.x router guides corroborate the classic IOS syntax used here; their availability does **not** establish feature support on every Packet Tracer model or image. Older command references are identified explicitly where they supply the exact classic command grammar. The generated scripts remain documentation-backed suggestions, with `semantic_validation: false`; existing support states and public request/mode contracts are preserved.

## Findings and corrections

| Area | Finding and resulting behavior |
| --- | --- |
| Interface contexts | The shared assessment parser intentionally recognizes structural interface strings but accepted `Loopback0/1`, `Lo0.1`, `Vlan1/2`, `Vlan10.1`, and out-of-range virtual units for generation. A router-local validator now rejects them, bounds interface text to 128 bytes, limits loopbacks to 0–2147483647 and VLAN interfaces to 1–4094, and is reused for both static-route families. These checks establish syntax, not interface existence. |
| Serial prerequisites | ISR4321 serial-interface uncertainty was rejected only for IPv4 static routes. The same rejection now applies to interface, ACL attachment, NAT role, and IPv6 static-route generation because the request carries no module evidence. Router2911 serial requests remain supported subject to the documented existing-interface prerequisite. |
| Interface addressing | Reject zero IPv4 masks and conservatively limit /32 generation to loopbacks. Preserve /31 host endpoints with an explicit point-to-point prerequisite. Reject IPv6 `::1` and IPv4-mapped addresses from this bounded interface workflow; global/ULA unicast and the separate FE80::/10 link-local family remain available. IPv4-mapped IPv6 route next hops are also rejected. |
| OSPF | The shared area parser accepts Rust numeric syntax such as `+1` and preserves it into command text. The router generator now requires unsigned decimal digits or dotted IPv4 area notation before invoking that parser. Explicit process, area, network/wildcard, host-bit rejection, and router mode remain intact. |
| RIP/EIGRP | Current guides confirm existing classic router modes and network statements. RIP continues requiring an explicit classful major network and version; EIGRP retains the supplied AS and derived wildcard. No automatic summary, passive-interface, authentication, or redistribution policy is inserted. |
| ACL | Named ACL application previously accepted `1LAN`, `_LAN`, and `-LAN`; it now requires an initial ASCII letter. Existing numbered IPv4 ranges and named identifier length/character limits remain intact. Standard ACL source wildcards may legitimately be noncontiguous and are not treated as subnet masks. |
| NAT | Existing one-to-one inside source syntax and interface roles match current documentation. Router-local interface checks now apply uniformly. Translation conflicts, inside/outside topology, reachability, and address ownership remain explicit prerequisites rather than inferred changes. |
| DHCP | Pool validation checked only the first address, permitting `128.0.0.0/1` to include multicast/reserved space and `64.0.0.0/2` to include loopback space. Pools and exclusion intervals now reject such spans, including exclusions whose individually unicast endpoints straddle 127/8. Numeric pool names remain valid and are deliberately handled differently from ACL names. |
| Bounds | Existing shared safe-text checks limit parameter values to 512 bytes and reject controls and command separators; description remains capped at 240 bytes and names at 128 bytes. The new interface bound applies to direct interface parameters and embedded static-route targets. No unbounded CLI fragment is introduced. |

Prerequisite metadata now explains Ethernet subinterface encapsulation and parent state, point-to-point /31 addressing, on-link assumptions for interface-only routes, OSPF adjacency requirements, DHCP pool selection by receiving interface/relay, and explicit exclusions for externally assigned infrastructure addresses. Applicable registry source URLs now point at the pages actually reviewed.

2. [IPv6 addressing and basic connectivity, IOS XE 17.x](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-addressing/b-ip-addressing/m_ip6-add-basic-conn-xe.html): address assignment, unicast forwarding, and prohibition on assigning the IPv6 loopback address to physical interfaces. Blanket rejection of `::1` in this generator and rejection of mapped addresses are conservative product scope, not a claim that every IOS context has the same restriction.
3. [Classic IPv6 address command reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipv6/command/ipv6-cr-book/ipv6-i1.html): `ipv6 address` and explicit `link-local` interface grammar.

VLAN generation remains the pre-existing bounded 1–4094 subset; this does not adopt broader platform-specific ranges from the guide.

[IPv6 static routing, IOS XE 17.x](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_ip6-route-static-xe.html): prefix/target syntax, fully specified routes, link-local interface scope, and the up/IPv6-enabled prerequisite for directly attached routes. Ethernet-only IPv6 routes are documented and remain accepted.
8. [OSPF configuration, IOS XE 17.x](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_iro-cfg-0.html): router process mode, network/wildcard/area grammar and peer coordination. IOS documents process IDs through 65535; the existing product contract reserves 65535 as an assessment sentinel and still rejects it. This audit does not describe that product restriction as an IOS limit.
9. [EIGRP configuration, IOS XE 17.x](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_ire-enhanced-igrp.html): classic AS mode and network/wildcard syntax.

[Classic ACL creation/application, IOS 15SY](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/sec_data_acl/configuration/15-sy/sec-data-acl-15-sy-book/sec-create-ip-apply.html): standard ACL number ranges, permit/deny and interface direction. [Cisco named ACL command reference](https://www.cisco.com/E-Learning/bulk/public/tac/cim/cib/using_cisco_ios_software/cmdrefs/ip_access-list.htm): names start with a letter and contain no spaces or quotation marks. [DHCP server configuration, IOS XE 17.x](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-addressing/b-ip-addressing/m_config-dhcp-server-xe.html): global exclusions; pool network, default-router and DNS options; numeric/symbolic names; interface/relay-based pool selection. Reserved-span rejection is a conservative client-subnet policy, not a newly asserted CLI grammar limitation.

## Regression coverage and validation

Six added regressions cover invalid virtual units in direct configuration and both route families; serial module uncertainty across five families; special IPv6 addresses and IPv4 masks; named/numbered ACL boundaries; OSPF signed areas and description limits; and DHCP reserved-space spans while retaining numeric pool names. Existing tests exercise rendering contexts, static administrative distance and link-local scope, RIP/EIGRP network statements, ACL/NAT, DHCP subnet gateways, and the distinction between documentation and PT evidence.

Validation: `cargo test -j 2 --test cisco_router` passed all **14 tests**, with zero failures. `rustfmt --check --edition 2024` on the five changed Rust files and `git diff --check` also passed. The first test run built fresh dependencies in approximately four minutes with the requested two-job limit. Packet Tracer execution and live-router execution were **not performed**.

## Remaining limits

- Physical port availability, module inventories, router-image support, VLAN/encapsulation state, duplicate native VLANs, overlapping interface subnets, shutdown state, neighbor compatibility, ACL definition/order, NAT collisions and DHCP service/conflicts require topology/current-configuration evidence not present in `CommandRequest`.
- The /32, special IPv6, virtual unit and DHCP reserved-span checks are intentionally bounded generation policies. Passing validation establishes only this supported subset, not broad IOS or Packet Tracer acceptance.
- Existing unsupported forms remain unsupported, including IPv4 fully specified interface-plus-next-hop routes, VRFs, tracking, Null0 targets and additional dynamic-routing policies. No ambitious new families were added.
- Shared assessment parsers remain unchanged: structural interface names and signed numeric OSPF areas may still be recognized for inspection. This generator checks those inputs before producing router commands; other consumers need their own generation safeguards.
- No push or release should infer PT runtime validation from this audit.
