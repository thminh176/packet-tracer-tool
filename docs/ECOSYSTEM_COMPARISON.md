All four HEAD hashes still match the table. GitHub API requests were rate-limited during this update, so last-push/archive fields are retained from the earlier snapshot rather than newly certified. A recent push does not promise ongoing maintenance, and an old push does not prove abandonment.

## Rust pktfile 0.2.2 is not a separate competing application

The [crate release record](https://crates.io/api/v1/crates/pktfile/0.2.2) identifies `TantiE100/pktctl`, MIT, published 2026-09-28, not yanked at audit time. Registry `.cargo_vcs_info.json` identifies commit `b73344420af4a1be0489a435968808b12e104195`, path `crates/pktfile`; its [README](https://github.com/TantiE100/pktctl/blob/b73344420af4a1be0489a435968808b12e104195/crates/pktfile/README.md) describes a Rust PKT reader/writer and XML editing helpers, requiring Rust 1.88+. It is an embeddable crate, with no standalone platform certification inferred. The root dependency is exactly `pktfile = "=0.2.2"`, patched to `vendor/pktfile`; local changes bound decompression and upgrade quick-xml 0.38 to 0.41 (currently resolved 0.41.0), with no local cryptographic changes; see [provenance](PROJECT_PROVENANCE.md). PKT decoding support does not establish support for every PKA variant.

## Disambiguating pkt-core

Here `pkt_core` means the Python package inside **aacanadaa/packet-tracer-pkt-format**, whose pinned [pyproject.toml](https://github.com/aacanadaa/packet-tracer-pkt-format/blob/ce61cd619ccc34e593557b8e0820f671fdeb571d/pyproject.toml) names distribution `pkt-core`, author `aacanadaa`, GPL-3.0-or-later. It is unrelated to the Rust `pktfile` crate, pktctl's live PTMP client, or similarly named packet/cryptocurrency projects.

The [PyPI pkt-core 0.2.0 page](https://pypi.org/project/pkt-core/0.2.0/) says it was rebranded by Shamveel, whereas its source archive metadata still names `aacanadaa`. The [PyPI JSON record](https://pypi.org/pypi/pkt-core/0.2.0/json) has no project URL; its sdist `PKG-INFO` and `pyproject.toml` explicitly say GPL-3.0-or-later. The sdist SHA-256 is `81880c309d48d0be8914bec804526cdb98b6c2c0d7eeb7dd48a8fb613541c9f8`, uploaded 2026-10-16. Shared metadata/layout support a relationship, but **no verified publisher authorization or exact Git commit-to-PyPI mapping was established**. Do not silently equate the PyPI publisher with the GitHub owner or install the package as a trusted substitute.

Our differentiation is a narrow workflow: offline read-only activity inspection, retained checkpoint paths/weights, explicit unsupported/ambiguous results, English/Vietnamese UI and human-reviewed command previews. It is not a claim of superior correctness, speed, coverage or legal clearance. The [license audit](LICENSE_AUDIT.md) controls release readiness.
