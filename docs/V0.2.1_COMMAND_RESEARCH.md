# v0.2.1 Cisco command coverage research

Reviewed 2026-10-23 against main/v0.2.0 commit `47fb1b3`. This is a documentation-only review of public implementation and official Cisco references. Syntax support, assessment mapping, configuration verification, and native Packet Tracer grading are separate claims.

## IOS syntax and conditions

All configuration commands below require appropriate privileges and entry through `configure terminal`; save runs after returning with `end`. Check the exact device, interface and software image before applying suggestions.

| Intent | Classic IOS syntax and mode | Conditions and cautions |
| --- | --- | --- |
| IPv6 forwarding | `ipv6 unicast-routing`; inverse `no ipv6 unicast-routing`; global configuration | Enables forwarding between IPv6 interfaces, independently of interface addressing. Requires a routing-capable image and suitable IPv6 interface configuration. Disabling it affects IPv6 routing entries; do not infer intent from an address requirement. [IPv6 routing reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipv6/command/ipv6-cr-book/ipv6-i5.html), [15M&T setup guide](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipv6_basic/configuration/15-mt/ip6b-15-mt-book/ip6-uni-routing.html). |
| Ethernet VLAN subinterface | Select `interface <Ethernet-parent>.<subinterface-number>` in global configuration, then `encapsulation dot1Q <vlan-id> [native]` in subinterface configuration | Supply VLAN 1–4094 explicitly. Parent must be operational for traffic; configure encapsulation before subinterface IP addressing and align peer trunk/native VLAN settings. `native` requires an explicit requirement. Subinterface suffix and VLAN ID are independent: `.100` does not establish VLAN 100. Exclude service instances, ranges and Q-in-Q from this narrow mapping. [IOS 12.4 VLAN guide](https://www.cisco.com/en/US/docs/ios/12_4/lan_switch/configuration/guide/confvlan.html), [LAN switching reference](https://www.cisco.com/c/en/us/td/docs/ios/lanswitch/command/reference/lsw_book/lsw_b1.html). |
| Interface IPv6 processing | `ipv6 enable`; inverse `no ipv6 enable`; interface configuration | Enables IPv6 processing and generates a link-local address without requiring an explicit global address. Does not enable global forwarding. Removing it does not disable IPv6 processing when an explicit IPv6 address remains. [IPv6 interface reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipv6/command/ipv6-cr-book/ipv6-i1.html). |
| SLAAC | `ipv6 address autoconfig [default]`; inverse `no ipv6 address autoconfig`; interface configuration | Requires suitable received router advertisements to obtain prefixes; generated addresses depend on those advertisements. `default` additionally installs a route via the selected default router and is restricted to one interface in this reference. Keep optional route installation separate from basic SLAAC intent. Removal can affect existing IPv6 addresses, so defer automatic removal. [IPv6 interface reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipv6/command/ipv6-cr-book/ipv6-i1.html). |
| Interface label | `description <string>`; removal `no description`; interface configuration | Requires an explicit interface and single-line text. The interface reference states a 238-character limit; current generator allows 240 bytes, so its boundary needs reconciliation rather than a claim of universal compatibility. [Interface description reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/interface/command/ir-cr-book/ir-d1.html). |
| Administrative state | `shutdown` or `no shutdown`; interface configuration | Administrative enablement does not prove physical/link protocol availability. Inspect `show interfaces`; do not derive a command from an observed operational down state alone. [Shutdown reference](https://www.cisco.com/E-Learning/bulk/public/tac/cim/cib/using_cisco_ios_software/cmdrefs/shutdown.htm). |
| Save running configuration | `copy running-config startup-config`; privileged EXEC | Replaces saved configuration with current running configuration; review all current changes first and account for destination confirmation. Cisco also documents the precise filesystem form `copy system:running-config nvram:startup-config`; startup location can depend on platform configuration. Keep the existing canonical command. [15M&T configuration files guide](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/config-mgmt/configuration/15mt/config-mgmt-15-mt-book/cm-config-files.html). |

## What v0.2.0 already implements

Evidence: `src/cisco/router/interfaces.rs`, `src/cisco/basic.rs`, `src/cisco/mapping.rs`, `src/cisco/device_profile.rs`, and the assessment/legacy generation paths in `src/commands.rs`, read at the baseline above.

| Family / intent | Registry and assessment coverage at baseline |
| --- | --- |
| `router.interface.dot1q` | Generator exists with explicit Ethernet subinterface, VLAN and optional native flag. Mapping recognizes `vlanid` only under a path component equal to `802.1Q`; `encapsulation = EthernetEncapProcess` selects the family without supplying a VLAN. That case needs explicit named VLAN evidence, not suffix inference. |
| `router.interface.description` | Generator and `description` / `interfacedescription` aliases already exist when interface context is present. This is not a missing family or missing pair of aliases. |
| `router.interface.shutdown` | Registry family exists and accepts literal `shutdown` / `no shutdown` state. Typed assessment mapper has no state aliases, but legacy generation already handles `portstatus`, `interfacestatus`, `administrativestatus`, and `shutdown`. Positive administrative status means `no shutdown`; positive shutdown means `shutdown`. Existing textual state parsing rejects numeric encodings. |
| `basic.save` | Generator and `save` / `saveconfiguration` mappings exist for exact resolved values `true`, `yes`, `startup`. An incomplete alias match is not an absent save command. |
| Static interface IPv6 | `router.interface.ipv6` and `router.interface.link_local` exist with assessment aliases and explicit address/prefix handling. They do not establish global forwarding or SLAAC intent. |
| IPv6 forwarding | `router.ipv6.routing` already exists in `src/cisco/router/routing.rs`; the missing piece at baseline is the assessment mapping and its field-specific Boolean interpretation. |
| IPv6 enable, SLAAC | Separate interface families and assessment mappings are added by this patch; a static address requirement alone does not establish either intent. |

Named completion uses unique `commands:parameter:<name>=<value>` evidence; missing or conflicting context must remain visible. IOS manuals establish CLI semantics, not numeric PKA flag meanings or assessment field equivalence.

## Prioritized next mappings

1. Preserve existing dot1Q and description mappings; add only evidence-backed label variants. Require explicit subinterface and VLAN, retain native intent separately, and reject conflicts. For example, synthetic `GigabitEthernet0/0.100` plus explicit VLAN `20` should retain VLAN 20; suffix-only input must remain incomplete.
2. Route existing textual administrative aliases through the existing typed shutdown family while preserving legacy polarity and conflict checks. Expand save value normalization only for documented application-level values; retain an explicit save requirement and emit save last. Neither needs a new IOS family.
3. Connect the existing global IPv6 forwarding family to the exact assessment field. This patch interprets 1/0 only for the specifically identified IPv6 Boolean fields, with regression tests and an impact warning when disabling forwarding. Generic numeric enums and inferred enablement from IPv6 addresses remain unknown. Cisco documentation establishes syntax, not PKA encoding.
4. Add separate interface families for explicit `ipv6 enable` and basic `ipv6 address autoconfig`. Require routed interface/model context and independently evidenced aliases. Defer SLAAC `default`, removal and implicit global routing until their extra effects have explicit requirements.

These priorities are recommendations, not implemented changes. Coordinator-owned synthetic checks should exercise missing VLANs, suffix/VLAN disagreement, state polarity, numeric ambiguity, conflicting metadata, unsupported models, and configuration mode/order before promoting mappings.

## Model and validation limits

Classic IOS documentation does not establish Packet Tracer command availability on every simulated 1941, 2911, 2960, 3560 or ISR 4321 image. ISR 4321 uses IOS XE; do not transfer hardware/image support from classic IOS without qualification. The current profile policy rejects 2960 routing/IPv6-routing capabilities and distinguishes unknown/documented support; this review provides no reason to bypass it. A 3560 multilayer capability is not blanket evidence for router Ethernet subinterfaces or any specific IPv6 command.

Suggested manual review points are running interface configuration, `show interfaces`, IPv6 interface/routes where supported, and `show startup-config` after saving. These are proposed checks only. No Packet Tracer execution, native grading, private activity inspection, protected-source copying, Rust changes, cargo runs or runtime tests were performed; only the public files named above and linked Cisco pages were reviewed. There is no measured coverage percentage or proof of numeric assessment encodings.
