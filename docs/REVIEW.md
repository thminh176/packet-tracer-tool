# v0.1.0 source and publication review

Review date: 2026-10-22. Reviewed source baseline: `8d6476803d8d6b13de0ae3c9d1c20e90493421a4`. This is a source assessment, not a certification of Cisco compatibility or a completed release acceptance test. Findings describe that baseline; subsequent fixes require their own verification.

**Verdict: the baseline is blocked; the coordinator's reviewed follow-up source is conditionally acceptable for conservative inspector scope.** Follow-up inspection of the coordinator's working changes found fixes for the R1 path amplification, R2 stale staging and R3 checksum/tip-document disclosure, plus R4 bounded reads and matching budgets. No additional source blocker was identified in that follow-up. Publication still requires updated regressions, dependency/security results and a final Windows artifact/content check; these pending gates are not asserted complete here. R5–R8 remain nonblocking limitations.

The follow-up preflight enforces 512-byte labels, 4,096-byte paths and assessment values, an 8 MiB aggregate path budget and 50,000 terminal nodes before extraction. Matching is capped at five million device/checkpoint pairs and fifty million snapshot-node/checkpoint operations; excessive comparisons remain Unverified. These are defensive application limits, not a process-level memory sandbox. Staging now refuses an existing versioned package directory, checksums use relative filenames, and the internal identifier was removed from the tip document. Broad docs/catalog copying and historical metadata still require publication review. The table retains baseline findings to make remediation traceable.

## Positive controls verified in source

- The application reads activity/progress sources and does not call the vendored encoder for user files. No device command execution, network client, activity score rewriting or password bypass was found in application paths.
- XML is limited to 64 MiB, one root, 128 levels and one million elements; malformed end tags, duplicate attributes, unknown entities and DTDs are rejected. Recursion is depth-limited. The decoder patch bounds decompressed output to declared size plus one and rejects mismatches. These controls do not resolve R1 or R4.
- Unknown/custom/variable/ambiguous assessments remain Unverified. Snapshot roles are not inferred by position. Explicit values and supported identity/semantic checks drive comparison.
- Command interpolation uses narrow character/grammar checks, interface-specific contexts, and explicit unsupported explanations. No direct newline/control-character command injection was found. Device commands are suggestions only.
- Export writes use a sibling exclusive temporary file, flush before rename, and protect loaded source identities and Packet Tracer extensions. Hardlink/source-preservation and failed-write cleanup have automated coverage. This is not a claim against a malicious process concurrently replacing filesystem entries.

## Dependency and Windows release gates

`Cargo.lock` and `--locked` application builds pin the application graph; the local MIT `pktfile` patch and provenance are documented. The standalone vendored test command resolves its own ignored lockfile, so its test dependency versions can differ from the application graph. Use the application graph as the primary shipped dependency inventory.

The coordinator owns installation/execution of `cargo-audit` and `cargo-deny`. Its reported first audit found R9 and unmaintained-package warnings for `ttf-parser` 0.25.1, `zbus_names` 4.3.5, `zvariant` 5.15.1 and `zvariant_derive` 5.15.1. Audit remediation and deny/license results remain pending at report completion; this worker did not independently run or verify those tools. Evaluate warning reachability on the shipped Windows graph before accepting exceptions. No clean vulnerability/license verdict is asserted. Check advisory freshness and inventory the actual runtime graph and bundled license texts. CI currently uses moving action tags and stable/latest toolchains rather than immutable revisions; pinning and an explicit toolchain/MSRV policy improve reproducibility. Shipping available license files does not establish complete license compliance on its own.

The build script does not explicitly force an x86_64 target despite its archive name. Validate target architecture, executable imports/runtime prerequisites, launch on a clean supported Windows machine, language files, ZIP contents and relative checksums. Code signing, a clean-machine launch and final native clipboard/save-dialog acceptance are not established by this review. No remote publication or GitHub mutation was performed.

## Verification and frozen scope

The default application suite at the reviewed baseline passed: **68 tests, zero failures, one opt-in private-file test ignored**. `cargo clippy --locked --all-targets -- -D warnings` passed, and the standalone vendored codec suite passed **18 tests**. This run did not access real private fixtures. A small external Rust harness confirmed R1 without modifying repository source or retaining decoded data. These executions cover the baseline; the coordinator must run the added resource/command regressions against the follow-up changes. Its command deduplication now uses a linear search per plan, so very large unique-plan groups can still impose quadratic work; this is a nonblocking performance limitation within the frozen manual-review scope.

Freeze v0.1.0 as an offline, read-only inspector for the modern authenticated container family and supported explicit XML semantics, with manually reviewed CLI/GUI suggestions. Selected-tree interpretation is inferred, real unlabeled snapshots remain Unverified, and synthetic command grammar coverage does not certify real schema extraction or native grading equivalence. Do not expand scope to activity editing, bypass, password recovery, script execution, universal grading, or unverified private baseline/count claims to close this release review.
